## 6단계 프로세스

```
Phase 1. 요구분석   → 기획자 AI     → 요구사항 명세서     → 카이 확인 ✅
Phase 2. 설계 확정  → 아키텍트 AI   → 워크플로우 설계서   → 카이 확인 ✅
Phase 3. 구현 배분  → 전문가 AI들   → 각 산출물 취합      → 취합 완료
Phase 4. 검수       → 검수자 AI     → 검수 보고서         → 카이 확인 ✅
Phase 5. 문서화     → 지니          → 최종 문서           → Obsidian 저장
Phase 6. 배포 승인  → 카이 최종 OK  → 완료 선언
```

---

## 시작 방법

### Claude 데스크탑에서 사용하는 방법

**1단계: 지니 호출 (오케스트레이터)**
```
이 파일 폴더의 내용을 컨텍스트로 제공하거나,
00_지니_오케스트레이터.md를 Claude에게 붙여넣기 후:

"지니, 시작해줘. [요청 내용]을 자동화하고 싶어."
```

**2단계: 지니가 Phase별로 전문가 호출**
```
지니가 자동으로:
1. 기획자 AI 역할 수행 (또는 호출 안내)
2. 카이 확인 요청
3. 아키텍트 AI 역할 수행
4. 카이 확인 요청
... 순서대로 진행
```

**3단계: 전문가 직접 호출 (단독 사용 시)**
```
특정 전문가만 필요할 때:
"n8n 전문가, Webhook 노드 설정 방법 알려줘.
참조문서(01_참조문서_n8n.md)를 기준으로 설명해줘."
```

### 문서 업데이트 트리거

## 카이 확인 포인트 체크리스트

Phase 1 완료 시 카이가 확인할 것:
```
□ 트리거 방식이 맞는가?
□ 입력 데이터가 모두 포함되었는가?
□ 출력(저장 위치, 알림 대상)이 맞는가?
□ 카카오 알림톡 사용 시 딜러사 계약 여부 확인
□ 미확인 사항 항목에 답변
```

Phase 2 완료 시 카이가 확인할 것:
```
□ 노드 목록이 요구사항과 맞는가?
□ 데이터 흐름도가 이해되는가?
□ Notion DB 스키마가 기존 운영 방식과 충돌하지 않는가?
```

Phase 4 완료 시 카이가 확인할 것:
```
□ Critical 이슈가 모두 해결되었는가?
□ 테스트 시나리오 결과가 모두 통과인가?
□ 배포 승인 여부
```
